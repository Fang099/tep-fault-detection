Each model reads one 3-minute snapshot of the 52 process variables and outputs a fault score. An alarm goes off when the score passes a threshold. Pick a model, move the threshold, and see what it catches and what it misses.

The alarm threshold

Rows above the threshold raise an alarm. Lowering it catches more faults but also raises more false alarms on normal operation. Every model on this site is compared at the threshold that gives 5% false alarms on validation data.

LearnHow sure are these numbers?

The validation set holds only a limited number of runs per fault type, so every metric would come out a little different with other runs. To measure that, the pipeline repeats the evaluation on 200 resampled versions of the validation set (a bootstrap): each time it draws whole runs at random, with replacement, keeping the same number of runs per fault type. Whole runs are drawn, not single rows, because rows within a run are strongly correlated; resampling rows would pretend there is far more independent evidence than there is.

The 95% interval is the range covered by the middle 95% of those 200 results. Intervals are computed at each model's 5% false-alarm threshold, so they appear in the tiles only at that setting.

Every threshold at once: the ROC curve

Each point on the curve is one threshold: the share of faulty rows caught against the share of normal rows that raise a false alarm. A model that guesses at random follows the diagonal. The dot is your current threshold; click the curve to move it.

PR-AUC summarizes precision against recall over all thresholds. Because most validation rows are faulty, even the majority baseline scores about 0.91 on it, so ROC-AUC and the false alarm rate say more here.

LearnWhat the area under the curve means

The area under the ROC curve has a direct meaning: pick one faulty row and one normal row at random. The AUC is the chance that the faulty row gets the higher score (ties count as half).

Choosing the threshold by cost

A false alarm costs an operator's time and trust; a missed fault can damage equipment, spoil product or create a safety risk. If you can say how much worse a miss is than a false alarm, the threshold that minimizes the expected cost follows.

For a threshold t, a fraction FAR(t) of normal samples raise a false alarm and a fraction 1 − recall(t) of faulty samples are missed. If a fault is present a share π of the time, and a miss costs r false alarms, the expected cost per sample is:

The chart divides this by the cost of having no alarms at all (π r, every fault missed), so 100% means monitoring is no better than nothing and lower is better. The share π matters a lot: in the validation data 91% of samples are faulty because of how the simulations were set up, but a real plant runs normally almost all the time. With a small π, false alarms dominate and the best threshold moves up; with a large one, misses dominate and it moves down.

LearnWhat the 30-minute history inputs add

A single 3-minute snapshot can't show a slow drift or a sensor that has started to fluctuate more. History inputs give the model the last W = 10 samples (30 minutes) of each reading, summarized as a mean and a standard deviation:

Only samples up to the current time t are used, and only from the same run, so a prediction never uses information that wouldn't be available at that moment. The mean smooths out noise; the standard deviation reacts when a sensor becomes more variable, which is how the "random variation" faults (8 to 12) show themselves. The price: right after a fault starts, the window still holds mostly pre-fault samples, so the very first minutes can be slower to catch.

Can the scores be read as probabilities?

A model is calibrated if its scores mean what they say: of all the samples it scores around 0.8, about 80% really are faulty. Each dot groups the validation samples with similar scores; on the diagonal, the score matches the true share of faults.

LearnMeasuring calibration: Brier score and ECE

The Brier score is the mean squared difference between the score pi and what happened (yi = 1 for a faulty sample, 0 for a normal one). Lower is better. The expected calibration error (ECE) averages the gap between each bin's mean score and its true share of faults, weighted by how many samples fall in the bin:

Calibration and ranking are different things. Every alarm on this site is set by a threshold, which only depends on the order of the scores, so a badly calibrated model can still detect faults well. Calibration matters when a score is read as a probability, for example when an operator is told "82% chance of a fault". Two common causes of miscalibration here: balanced class weighting pushes scores toward the middle on purpose, and trees and forests give coarse, overconfident scores. These numbers are also tied to the validation set's 91% share of faulty samples; with a different share the same scores would be calibrated differently.
