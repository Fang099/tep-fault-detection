Run everything yourself

All code is in the GitHub repository. The pipeline trains every model, chooses thresholds and models on validation, runs the final test, and writes the files this website reads.

Get the data

Download the four CSV files from the Kaggle dataset afrniomelo/tep-csv into one folder, keeping their names:

TEP_FaultFree_Training.csv   TEP_Faulty_Training.csv
TEP_FaultFree_Testing.csv    TEP_Faulty_Testing.csv

The first run converts each CSV to a compressed Parquet file next to it, so later runs load in seconds.

  • Access. Downloading from Kaggle needs a free account. The data is not stored in the repository: the four files hold about 15 million rows. The licence is stated on the dataset's page; the original files were published on Harvard Dataverse (Rieth et al., 2017).
  • No keys in the repository. The code never asks for a Kaggle key: it only reads the CSV files from the folder you give it. If you download with the Kaggle command-line tool, keep its kaggle.json key outside the project folder.

What the pipeline does, step by step

Everything is in one script, tep_pipeline.py, and every random choice uses the same seed (42), so a rerun on the same data and package versions makes the same split and the same models.

  1. Load the two training files and label each row: faulty if faultNumber > 0 and sample > 20 (160 in the test files), otherwise normal.
  2. Split by simulation number. The 500 simulation numbers are divided 80% / 20% at random (seed 42). A number goes to the same side for all 21 kinds of run (fault-free and faults 1 to 20), giving 8,400 training runs and 2,100 validation runs. The script stops if any simulation number is on both sides, and counts validation rows identical to a training row (0).
  3. Build the inputs: the 52 readings, and for the history models their rolling mean and standard deviation over the last W samples of the same run. Standardizing is fitted on the training runs only.
  4. Train every model and setting on the training runs.
  5. Score on validation. For detection, the threshold is the score that 5% of normal validation rows exceed. The best detection model catches the most faulty rows at that threshold; the best diagnosis model has the highest macro-F1. Windows longer than one hour and the SVM are shown but cannot be chosen.
  6. Intervals: 200 resamples of whole validation runs, within each fault type.
  7. Final test (--final-test): the chosen models are fitted again on training and validation runs together and scored once on the test files, with the validation thresholds unchanged. The exact validated models are scored too.
  8. Export the results as JSON files for this website.

Run on Google Colab

  1. Put the CSVs in a Google Drive folder, for example MyDrive/TEP.
  2. In Colab, open File → Open notebook → GitHub, enter Fang099/tep-fault-detection and open run_colab.ipynb.
  3. Set DATA_DIR to your folder and run the cells in order. Finished models are saved to Drive, so an interrupted run continues where it stopped.

Run on any computer

git clone https://github.com/Fang099/tep-fault-detection.git
cd tep-fault-detection
pip install -r requirements.txt

python tep_pipeline.py --data-dir path/to/csvs --runs-per-fault 100   # subset: faster
python tep_pipeline.py --data-dir path/to/csvs --runs-per-fault 0     # all 500 runs per fault
python tep_pipeline.py --data-dir path/to/csvs --runs-per-fault 0 --final-test
OptionDefaultMeaning
--runs-per-fault100Use the first N runs of each fault type; 0 means all 500.
--familiesallModel families to train, comma-separated: logreg,pcalr,pcamon,tree,rf,gb,ada,xgb,svm. Finished models are always skipped, so --families svm adds just the RBF SVM to finished results.
--history-familieslogreg,pcamon,rf,xgbFamilies also trained with 30-minute rolling mean and standard deviation inputs; an empty string turns this off.
--hist-windows2,5,20,40Other history windows, in 3-minute samples, for the window sweep: the best 30-minute settings of each history family are retrained with each. An empty string skips the sweep.
--det-stride1Detection trains on every k-th time step of each run (1 = every step).
--diag-stride1Diagnosis trains on every k-th time step (1 = every step).
--selection-far0.05False-alarm rate used to set thresholds and pick the best detection model.
--test-runs-per-fault0Faulty test runs used per fault type in the final test; 0 = all 500.
--learning-curve1Retrain the best detection and diagnosis models on fewer runs and sparser samples to measure how much data matters; 0 skips it.
--end-to-end1Score detection and diagnosis together with 21 answers: the two-model chain and one 21-answer model with the best diagnosis settings; 0 skips it.
--svm-rows5000,20000Training-subset sizes (random rows) for the RBF SVM. An exact kernel SVM's cost grows with the square of this, so it never uses all the data and is never chosen as the best model.
--svm-c1,10Values of C (margin softness) for the RBF SVM.
--split-demo01 = also measure what a random split by row would have reported (logistic regression and a deep tree, trained both ways on the same number of rows).
--final-testoffRetrain the chosen models on all training runs and evaluate once on test.
--force-retrainoffRetrain models even if their results already exist.

The full dataset needs a computer with 16 GB of memory. A free Colab session has less memory (about 12 GB) and stops after about 12 hours, so use it with a smaller --runs-per-fault. Training every model on all the data took more than a day of computing on a desktop PC; finished models are skipped on a rerun, so it can be done in pieces. Results go to outputs_<N>runs/ (or outputs_full/) inside the data folder: trained models in models_v3/ and the website files in web_data/.

Update this website

The website is plain HTML, CSS and JavaScript in the docs/ folder, served by GitHub Pages. It reads the exported results from docs/data/; nothing is trained in the browser.

  1. Copy the contents of web_data/ into docs/data/ (the Colab notebook's last cell downloads them as a zip).
  2. Commit and push. GitHub Pages updates within a minute or two.
  3. To preview locally: cd docs, then python -m http.server, and open http://localhost:8000.

How exact is a rerun?

  • Same split, same settings. The seed, the split and every grid of settings are fixed in the script.
  • Package versions. requirements.txt lists the minimum versions the code needs. The exact versions used for the published run were not recorded, so a rerun with other versions can differ in the last decimals.
  • Hardware. A different processor, number of cores or build of a library can change floating-point results in the last decimals.
  • What cannot be rerun from the website alone. The site stores each model's scores as distributions and a few example runs, not the trained models. A new question about the models, such as the false alarm rate by time since the start of a run (why it matters), needs the pipeline to be run again.
