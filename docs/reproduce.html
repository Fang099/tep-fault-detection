Run everything yourself

All code is in the GitHub repository. The pipeline trains every model, chooses thresholds and models on validation, runs the final test, and writes the files this website reads.

Get the data

Download the four CSV files from the Kaggle dataset afrniomelo/tep-csv into one folder, keeping their names:

TEP_FaultFree_Training.csv   TEP_Faulty_Training.csv
TEP_FaultFree_Testing.csv    TEP_Faulty_Testing.csv

The first run converts each CSV to a compressed Parquet file next to it, so later runs load in seconds.

Run on Google Colab

  1. Put the CSVs in a Google Drive folder, for example MyDrive/TEP.
  2. In Colab, open File → Open notebook → GitHub, enter Fang099/tep-fault-detection and open run_colab.ipynb.
  3. Set DATA_DIR to your folder and run the cells in order. Finished models are saved to Drive, so an interrupted run continues where it stopped.

Run on any computer

git clone https://github.com/Fang099/tep-fault-detection.git
cd tep-fault-detection
pip install -r requirements.txt

python tep_pipeline.py --data-dir path/to/csvs --runs-per-fault 100   # subset: faster
python tep_pipeline.py --data-dir path/to/csvs --runs-per-fault 0     # all 500 runs per fault
python tep_pipeline.py --data-dir path/to/csvs --runs-per-fault 0 --final-test
OptionDefaultMeaning
--runs-per-fault100Use the first N runs of each fault type; 0 means all 500.
--familiesallModel families to train, comma-separated: logreg,tree,rf,gb,ada,xgb. Finished models are always skipped.
--det-stride2Detection trains on every k-th time step of each run.
--diag-stride5Diagnosis trains on every k-th time step.
--selection-far0.05False-alarm rate used to set thresholds and pick the best detection model.
--test-runs-per-fault100Faulty test runs used per fault type in the final test.
--final-testoffRetrain the chosen models on all training runs and evaluate once on test.
--force-retrainoffRetrain models even if their results already exist.

Results go to outputs_<N>runs/ (or outputs_full/) inside the data folder: trained models in models/ and the website files in web_data/.

Update this website

The website is plain HTML, CSS and JavaScript in the docs/ folder, served by GitHub Pages. It reads the exported results from docs/data/; nothing is trained in the browser.

  1. Copy the contents of web_data/ into docs/data/ (the Colab notebook's last cell downloads them as a zip).
  2. Commit and push. GitHub Pages updates within a minute or two.
  3. To preview locally: cd docs, then python -m http.server, and open http://localhost:8000.
