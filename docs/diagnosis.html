The price: reacting later

LearnWhy a longer window is not always better

A rolling mean over W samples averages away noise: its standard deviation shrinks roughly like 1/√W, so a small, steady shift that is invisible in one noisy reading stands out in the average. A rolling standard deviation needs several samples before it can tell that a sensor has become more variable. Both argue for longer windows.

But the window looks back in time. Right after a fault starts, a 2-hour window still holds about 40 pre-fault samples and only a few faulty ones, so the average barely moves yet. Long windows are therefore more sensitive to slow, subtle faults but react later to sudden ones, and some of their gain is offset by that delay. Picking W is a bias–variance trade-off over time: short windows are noisy (high variance), long windows lag (bias).

Choosing the window is model selection like any other setting, so it is done on the validation runs; the test set is not used.

How quickly is the right fault named?

For each faulty validation run: minutes from the moment the fault starts until the model names the correct fault 3 times in a row. Faded bars mean this happened in only some runs.

Three correct answers in a row can also happen by chance for a fault the model barely recognizes, especially over a long run. Long delays with a low share of runs should be read as "not reliably diagnosed".
